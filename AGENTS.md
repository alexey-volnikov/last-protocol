# AGENTS.md — Правила для Codex, ChatGPT и других агентов

**Прочитать этот файл ПЕРЕД ЛЮБОЙ работой с проектом.** Язык документации и обсуждений — русский; английский допустим для технических идентификаторов.

## 0. Зачем существует репозиторий

LAST PROTOCOL — симуляция автономных лунных роботов с настоящими ограничениями, частичным наблюдением и проверяемым обучением. На первом этапе нужен наблюдаемый примитивный эксперимент. Перспективный вектор сохранён в `docs/VISION.md` и `docs/IDEA_REGISTRY.md`.

## 1. Неприкосновенные принципы

1. **Один источник истины о мире** в движке; ИИ получает данные только через сенсоры/память/сообщения. UI-инструменты разработчика вправе показывать истину, но никогда не передают её агенту.
2. **Никаких фальшивых достижений.** Скриптовая эвристика называется эвристикой; нейросеть — нейросетью лишь после реализации и проверки. Не инсценировать заранее прописанное обучение.
3. **Физические причинно-следственные ограничения:** стоимость движения, сенсоров, вычислений, хранения, связи, света, холода, стройки; ни бесконечной энергии, ни бесплатной информации.
4. **Детерминизм с seed**, фиксированный шаг симуляции и журнал входов/действий/результатов для воспроизводимости.
5. **Память ограничена и типизирована.** Файлы наблюдений/карта, оперативная память и веса модели — разные ресурсы. Не стирать навык вождения при удалении фотографии.
6. **Три состояния отказа:** спячка/восстановление, ремонтируемое повреждение, необратимая потеря. 0% заряда не равен смерти; повторный запуск после полного отключения — на 70%, если физически доступно питание и допустима температура.
7. **Никаких телепортаций после сбоя.** Каждая следующая попытка физически обеспечена доступными корпусами, оборудованием и резервными данными. Для лабораторного reset явно отделить режим разработчика от лора.
8. **Расширение через отдельные системы:** в будущем строительство узлов, радио, карты, ремонтник, геолог, вода. Не связывать всё в один монолит.
9. **Не уничтожать прошлые идеи.** При пересмотре менять статус, добавлять решение и причину, историю правок сохранять в Git. Не удалять ID из реестра без одобрения автора.
10. **Не усложнять преждевременно.** Каждый этап должен быть запускаем и тестируем. Не вводить LLM или облачные API без явного решения.

## 2. Перед изменением

- Прочитать `README.md`, `docs/VISION.md`, `docs/IDEA_REGISTRY.md`, `docs/DECISIONS.md`, `docs/ROADMAP.md`, `docs/SIMULATION_CONTRACT.md`.
- Выбрать ровно одну узкую задачу; по возможности привязать к ID идеи `LP-###`.
- Зафиксировать гипотезу, критерий проверки, возможное влияние на совместимость сохранений/телеметрии.
- Если идея спорная или меняет основополагающий принцип — не принимать молча: добавить запись в `docs/DECISIONS.md` со статусом `proposed` и запросить решение владельца.

## 3. При изменении

- Минимальный дифф. Не переписывать ранее работающую часть лишь ради косметики.
- Отделять движок (`src/sim/`) от отрисовки (`src/ui/`) и UI. Физика не зависит от FPS.
- Запрещён доступ агентского кода к полному `world`/скрытым ресурсам. Передавать отдельное наблюдение с полями, доступными сенсорам.
- Показания датчиков, утраты информации и события должны быть причинно обоснованы и тестируемы.
- Добавлять тесты на граничные случаи, особенно 0/70% заряда, поведение в тени, лимиты памяти, seed, отключение сенсоров.
- Если функционал пока имитируется, пометить явно `mock` / `placeholder` и описать ограничение в README.
- Для настоящего обучения: сохранять модель, seed, экспериментальный протокол и сравнения с baseline; не выводить «обучился» из одного удачного прохождения.

## 4. После изменения

- Выполнить тесты, указать команду и результат. Если не удалось — честно сообщить.
- Обновить соответствующий пункт `docs/IDEA_REGISTRY.md`, `docs/ROADMAP.md`, документацию и при необходимости `docs/DECISIONS.md`.
- Добавить запись в `CHANGELOG.md` для заметных изменений.
- В отчёте владельцу дать: **что изменилось / что реально работает / что пока заглушка / как запустить / что дальше**.
- В GitHub использовать issues/PR, где доступны; не писать «создано», пока API не подтвердил действие. Ни ChatGPT, ни Codex не должны считать себя единственным агентом проекта.

## 5. Если контекст потерян

Начни с `README.md`, затем этот файл, затем `docs/IDEA_REGISTRY.md`, `docs/DECISIONS.md`, `docs/ROADMAP.md`, `docs/SIMULATION_CONTRACT.md`. Они составляют долговременную память проекта. Задачи и переписки дополняют, но не заменяют эти документы.

## 6. Ближайшая техническая цель

Стабильный, минимальный, честный 2D top-down мир: ровер + капсула; процедурный seed, отдельная «истина мира» и «знания робота», ограниченные энергия/память, сенсоры, скорость симуляции и телеметрия. Следом — повторяемое обучение управлению и возврату к базе на ранее невиданных картах. **Не обещать нейроэволюцию, пока она не работает.**

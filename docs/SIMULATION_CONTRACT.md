# Контракт симуляции v0 — что мир знает и что агент вправе знать

## 1. Уровни, границы

**World truth**: рельеф, препятствия, ледяные залежи, температура, тень, время, все позиции и ресурсы. Знает только физический движок и отладочный UI.

**Sensors**: массив показаний доступных устройств в момент времени (со временем шум, частота дискретизации, задержки, отказы). Ни полного seed/карты, ни скрытого льда.

**Memory**: результат прошлых наблюдений, ограниченная ёмкость, отдельные типы хранения (рабочая память, карта, сырые сканы, журнал, веса политики).

**Policy**: только `(observation, memory, mission, capabilities)` → `action, updatedMemory, computeBudget`. Никаких указателей на объект World в интерфейсе политики.

**Physics**: проверяет действия, расход энергии, время, температуру, контакт, последствия.

**Learning**: изменяет policy по траекториям, наградам и условиям; в будущем отдельный процесс тренировок. Нельзя делать вывод «понял причину» лишь на основе совпадения.

**UI**: может отображать две карты: объективная истина для разработчика и представление агента. Разделить их яркими подписями.

## 2. Системы ровера

- **Энергия:** Wh; стоимость движения, электроники, вычислений, сенсоров, связи, инструментов; зарядка только при реальном поступлении мощности. Аккумулятор ограничен температурой, допустимой мощностью, деградацией (будущее).
- **Тепло:** температуры поверхности, батареи и электроники; излучение в вакууме, солнце, изоляция и подогрев. MVP использует упрощённую модель с явным статусом approximation.
- **Режимы:** ACTIVE / LOW_POWER / HIBERNATING / DAMAGED / LOST. При 0% выключается, аппаратный контроллер (условный маломощный) отслеживает восстановление. Автозапуск после 0% при ≥70% и безопасной температуре; после *холодовой* остановки без полного разряда — при прогреве и достаточном меньшем резерве (тестовый порог 10%); без физической возможности зарядиться может остаться отключённым навсегда. Изначальный порог 70% — геймдизайнерская настройка, не закон электротехники.
- **Локация:** фактическая позиция vs оцениваемая позиция (позже с дрейфом и неопределённостью). Нет GPS на Луне по умолчанию. На раннем этапе маяки/капсула помогают переуточнению.
- **Сенсоры:** энкодеры, IMU, дальномеры/лидар, свет, температуры, напряжение/SoC, камера. Измерения различаются стоимостью и точностью.
- **Память:** лимит накопителя, выбор сжатия, удаление старых карт и фото, существенные исключения (прошивка/веса не хранятся в той же корзине).
- **Связь:** радиовидимость, дальность, мощность, пропускная способность, ошибка передачи; только в будущем.
- **Постройка:** реальная установка объекта, расход массы/энергии/материалов; не появляется из ниоткуда.

## 3. Время и научность

- Земные сутки = 86400 секунд; синодический лунный день приблизительно 29,53 земных суток вне полярных осложнений.
- Южный полюс требует геометрии низкого Солнца и локальных теней. Ускоренная смена света в лабораторном режиме допустима **только с отметкой `TEST/LAB`**, не считать её физическим симулятором Луны.
- «Энергия мысли» — измерять/моделировать через работу процессора, а не штрафовать за текст псевдоразмышлений.
- Содержать единицы физических величин и ограничения в config. Все условные параметры помечать как таковые.

## 4. Отказы и наследование

1. Временная остановка: холод и/или недостаточный заряд. При доступном нагреве/свете возможно восстановление **той же** версии и жизни.
2. Починка возможна: препятствие, датчик, колесо, манипулятор; зависит от механики ремонта и ресурсов.
3. Необратимая потеря: физическая невозможность ремонта/питания. Новая попытка существует только при наличии запасного корпуса или производства, переданных данных и энергии капсулы.
4. В dev-mode ручной reset допустим как внешний эксперимент, а не событие в лоре.

## 5. Набор событий и данных (будущий стабильный формат)

```json
{
  "schema_version": 1,
  "run_id": "example-id",
  "seed": 42,
  "engine_version": "0.0.1",
  "physics_preset": "lab",
  "sim_time_s": 3600,
  "rover_id": "rover-001",
  "generation": 1,
  "model_version": "baseline-heuristic-v0",
  "observation": { "battery_wh": 16.5, "sunlight": 0.2, "lidar": [] },
  "action": { "type": "move", "direction": 2 },
  "outcome": { "battery_delta_wh": -0.1, "distance_m": 1.0 },
  "event": "STEP"
}
```

Формат выше — **проектный пример, не обещание уже реализованного экспортёра**. Схему и параметры расширять только с версированием.

## 6. Настоящее обучение (будущее)

Обучение по многим seed, validation/test-seeds не участвуют в подборе. Baseline на правилах отдельно от policy NN. Сравнивать долю возвращений, метры безопасной разведки, Wh/метр, время без питания, объём памяти, потери роботов, число ошибок. Реальный рост проверять по нескольким запускам с одинаковыми наборами сценариев.

# Проверка устойчивости живого обучения · online-audit-v1

**Узкая задача:** LP-028/043, запрос владельца 16.10.2026 после вращения на карте 4233. Предыдущий benchmark проверял замороженные модели; это не проверка поведения во время дальнейшего обучения. Цель — воспроизвести деградацию, разделить причины и проверить небольшое изменение процесса обучения без заданных поворотов/маршрута.

## Протокол до сравнения вариантов

Исходные модель `curiosity-dqn-v1` E125261 и код — Git-ревизия `f3907e2`. Физика/награда/49 входов/5 действий сохраняются. Первый известный сценарий: шесть LAB-запусков по 2400 шагов с тем же мозгом/replay; сброс мира явно внешний, не возрождение в лоре. Отдельный сценарий: 43200 шагов (24 условных часа) одной физической жизни, без телепортаций и сбросов. Во сне нет решений или обновлений; пробуждение требует прежних 0/70% и температуры/света.

Карты диагностики 4233 и 42. Карты validation 10001–10003, seeds контроллера 71/909. Отложенные test-карты 11001–11004, seeds 73/917 не участвуют в выборе. Сравнивать baseline, сохранение отложенного отказа после LAB-reset, уменьшенный шаг обновлений и ограниченную смешанную память (только если понадобится). Проверять варианты по одному изменению, совместный вариант выбирать только по validation. Отложенный test запускается один раз после выбора, отрицательные результаты сохраняются.

После первых пяти validation-вариантов смешанная память оказалась лучше по основному критерию. До открытия test добавлены два сочетания: та же смешанная память + шаг 0.0003 и + шаг 0.0001. Это завершает подбор в этом аудите; новые параметры по результатам test не подбираются. Подробные оконные журналы хранятся локально в игнорируемой `experiments/runs/`, публичный отчёт содержит агрегаты каждого запуска, диагностические примеры и checksum полного локального журнала.

Фиксировать перемещения/посещения/наблюдения, число последовательных поворотов и долю поворотов, ожидания, работу/спячку, отключения, столкновения, расход, выполненные пробы и компоненты награды по действиям. Первые 300 шагов каждого запуска — отдельное окно: менее 1 м движения при ≥100 активных шагах и доле поворотов ≥70% считается LAB-признаком вращения, а не аппаратным запретом действия. Нулевая скорость во сне не считается вращением. Сравнивать ухудшение от первого запуска к последним трём.

Критерий выбора: меньше проблемных окон на validation (вращение или ≥100 активных шагов при <1 м движения, <5 новых наблюдений и отсутствии новых посещений); затем больше посещённых клеток в последних трёх LAB-запусках; при равенстве меньше отключений и столкновений. Проблемные окна — диагностический индикатор, не штраф/команда полити́ке; вращение и застой также записываются раздельно. Рост цифры E сам по себе не результат. Замороженный контроль полезен для диагностики, но не заменяет проверку включённого обучения.

## Найденная ошибка

`observe()` откладывает переход с отключением до следующего включения питания. Однако `newTrial()` стирает pending-переход. После LAB-сброса до пробуждения штраф за отказ исчезает из опыта; offline-обучение обрабатывало его через `finishLabTrial()`, браузерный reset этого не делал. Исправление должно сохранить отложенный переход и принять его при следующем акте с доступным питанием. Сам reset не вычисляет веса спящего ровера.

Исправление внесено: отложенный переход переживает `newTrial()`, в том числе если обновление весов временно выключено. При следующем решении с включённым обучением он попадает в replay однократно. Внешний LAB-контроль `legacy` намеренно воспроизводит прежнее стирание для сравнения; это не режим обычного интерфейса.

На известных картах выбранная смешанная память устранила раннее вращение после повторных reset в этом контроле. На карте 4233 в пятом запуске первые 300 шагов дали 18.81 м против 0.18 м у baseline. Это зафиксированный регрессионный случай, а не доказательство универсального решения. Средняя оценка за поворот в baseline на validation отрицательна (около −0.024); гипотеза бесконечного положительного бонуса за один и тот же скан не подтверждена. В 73 окнах вращения в среднем появилось лишь 8.86 новых клеток за окно 300 шагов. Точную роль отдельных представлений сети и bootstrapping этот аудит не устанавливает.

## Границы и совместимость

Снимки и оценка на других картах — работа внешней LAB-разработки; ровер не получает бесплатной скрытой проверки качества. Память переходов остаётся ограниченной. Нельзя автоматически объявлять новый алгоритм освоившим воду или возвращение. Старые отчёты и модели сохраняются с исходной provenance; любой изменённый процесс обучения указывает свою версию/настройки. Формат полного сохранения мира в этот этап не входит.

## Результаты

Команды последовательно: `npm run audit:online`, `npm run audit:online:known`, `npm run audit:online:test`. Первый запуск сравнивает все семь вариантов на validation и сохраняет выбранный. Далее известные случаи и отложенный test используют только legacy / исправление pending / выбранный вариант. Всего 72 сочетания карты, seed и варианта; каждое содержит шесть LAB-запусков и отдельную 24-часовую жизнь, всего 4 147 200 фиксированных шагов. Контроллер меняет веса во время испытания; это не прежняя frozen-проверка.

`experiments/online-audit-validation.json` содержит все варианты; `online-audit-diagnosis.json` — известные случаи, `online-audit.json` — отложенный контроль и использованную validation-запись. В каждом запуске есть действия, компоненты награды по действиям, первые 300 шагов, число проблемных окон и примеры. Полный локальный журнал указан в `rawDetails`; его SHA-256 считается по UTF-8 JSON без завершающего LF. Удаление локального журнала не делает публичный отчёт полным replay: сценарий воспроизводится кодом, исходной моделью и seed.

## Вывод для разработки

1. **Подтверждена ошибка жизненного цикла опыта.** LAB-reset стирал записанный отказ. Исправление покрыто тестами и применяется в обычных контроллерах; после reset отказ обрабатывается при следующем решении с включённым обучением, а не бесплатно во сне. Загрузка только весов по-прежнему не восстанавливает replay или отложенный переход: полного сохранения ещё нет.
2. **Проверять только frozen-мозг недостаточно.** Один и тот же checkpoint должен проходить проверку дальнейшего обучения, длительной жизни и LAB-reset с переносом опыта. Ускорение UI не меняет физический шаг и не является исправлением деградации.
3. **Состав опыта влияет на застревание.** Смешанная память помогает известному случаю и сокращает общий застой на новых картах. Вращение на новых картах почти не уменьшилось, а часть метрик ухудшилась. Этот вариант доступен в LAB-аудите; он не объявляется решением устойчивости и не подменяет обычную политику вручную заданным движением.
4. **Следующая узкая гипотеза:** сети может не хватать доступной истории собственного движения и результата действий, чтобы различать продуктивный обзор и повторение знакомого состояния. Проверить небольшой ограниченный сенсорный контекст и отдельный контроль состава опыта; не добавлять правило «после N поворотов ехать» и не подбирать параметры по уже открытому test. Эта гипотеза не установлена как причина данным аудитом.

Проверка кода: `npm test` — 45/45. Включены регрессия пяти повторных запусков карты 4233, сохранение отложенного отказа через reset/выключение обучения, отсутствие обновлений во сне, границы смешанного replay, реальные детерминированные изменения весов и согласованность отчётов/хешей. Старые frozen-артефакты сохранены с исходными Git-ревизиями.

# Память о капсуле · LP-050 / D-026

## Гипотеза и протокол до реализации

17.10.2026, запрос владельца: отрицательный сигнал при утрате из памяти местоположения капсулы. Это заданная инженером мотивация, не самостоятельно придуманная цель и не готовая команда возврата. Проверяем, помогает ли она сохранять сведения без замены разведки стоянием у старта.

Узкая задача — отдельный LAB памяти капсулы. Проверка использования видимых препятствий остаётся в плане; алгоритм объезда/распределение replay в этом опыте не меняются. Физическая зарядка капсулы и сеть узлов — следующие задачи, не часть этой реализации.

Сведения о капсуле — одна обычная запись в карте 192 KiB / 512 клеток, без защищённого слота. В начале она известна по месту высадки. Новые наблюдения могут вытеснить её. Восстановление — только оплаченный скан капсулы в пределах 7 m с прямой видимостью; относительное измерение переводится в оценённые координаты через одометрию. Простое удаление записи, отсутствие сигнала маяка или удалённость сами по себе не дают скрытых координат. Маяк в пределах 9 m сохраняет прежнее доступное направление, но не является бессрочной копией положения. Его обработка включена в существующие условные расходы электроники, распознавание капсулы — в оплаченный скан.

Штраф **−2 один раз при переходе «запись была → записи нет»**. Нет ежешагового штрафа за неизвестность, положительного бонуса за повторное нахождение, стирания навыков/весов, принудительного разворота или завершения попытки. Сон сохраняет память без сканов и обучения. Потеря записи не означает доказанную потерю всей возможности вернуться; память положения, живой маяк и проходимый маршрут различаются. Сохранённая точка не доказывает известный путь.

Политика `capsule-dqn-v1`, schema 6, 69→32→5: прежние 61 вход + восемь (известность точки, cos/sin относительного направления и нормированная дальность до запомненной точки, доступность маяка и cos/sin его направления, возраст записи). Перенос 61→69 явный с нулевыми новыми связями. Все старые профили и ключи сохранений сохраняются отдельно; новый LAB не имеет бессрочного mission.rememberedHome. Сводка schema 5 включает новый режим/память; полноценного сохранения мира/replay по-прежнему нет. Симулятор 0.4.0.

Сравнение: одинаковые датчики, конечная память, модель, действия и затраты; варианты penalty=0 и penalty=2. Два тренировочных seed 1801/3109, по 80 эпизодов × 2400 шагов на картах 21001–21016. Validation: 22001–22003 × seeds 137/947. Test: 23001–23004 × seeds 139/953, открывается после фиксации выбора по validation. Оценка каждого: шесть LAB-reset по 2400 шагов с общими весами/replay, отдельно 43200 шагов одной жизни с новой копией мозга; epsilon 0.06, окно застоя 300 шагов, сон исключён. Дополнительно исходные перенесённые веса с включённым штрафом. Ранги выбора внутри каждой обученной группы: меньше проблемных окон; затем меньше потерь записи; затем больше покрытие поздних попыток; затем меньше отключений/столкновений. Выбор фиксируется до test.

Полный критерий на validation и test: у штрафуемого варианта меньше потерь записи, чем у контроля без штрафа и у исходных весов; проблемных окон не больше; покрытие жизни и поздних попыток (посещённое/наблюдённое) ≥90% каждого контроля; отключений и столкновений суммарно не больше. Нулевые потери при стоянии не считаются успехом. При невыполнении публикуется результат и не заявляется выученный возврат. Базовый комплект нового LAB остаётся явным переносом, если выбранное дообучение не улучшило полный validation-критерий относительно исходных весов.

Проверки механики: реальное вытеснение при бюджете, отсутствие наказания только за выход из радиуса, однократность потери, отсутствие бонуса при повторном нахождении, окклюзия и выключенные/неоплаченные сканы, сон/0–70%, изоляция от world и бессрочной точки, отдельность весов, детерминизм, несовместимые схемы/явный перенос. Проверка сравнения содержит модель, исходные SHA-256, все новые карты/seeds и checksum подробного журнала.

Логический бюджет replay для 69 входов — 284 KiB / 512 переходов; окно действий остаётся 1 KiB, запись капсулы занимает общую карту. Реальный heap JavaScript не измеряется. Новые входы и работа с записью включены в условные прежние бюджеты CPU 2.2 W / обучения дополнительно 4 W; оплата сенсорного распознавания включена в скан, это LAB-приближение процессора/прибора. Отдельного действия закрепить, удалить или сжать запись пока нет: из доступных пяти действий повторное сканирование обеспечивается прибытием в видимую область. Зарядка и выгрузка у капсулы отсутствуют; штраф сам по себе не создаёт физической пользы возвращения.

## Результат

Четыре тренировки и 54 живых сценария, всего 3 878 400 физических шагов. Validation выбрала control-3109 (E233277) и penalty-1801 (E232106); выбор записан до открытия test. Комплект нового LAB остался исходным переносом E198828: полному validation-критерию дообучение не удовлетворило. Полный критерий также не выполнен на test.

| Метрика | Validation: исходный / без штрафа / со штрафом | Test: исходный / без штрафа / со штрафом |
|---|---:|---:|
| Потери записи | 22 / 38 / 18 | 24 / 50 / 28 |
| Повторные измерения после потери | 2 / 1 / 3 | 0 / 2 / 6 |
| Вращение или застой, окон | 7 / 14 / 85 | 52 / 21 / 125 |
| Посещено за жизнь, среднее | 116.5 / 160.7 / 146.3 | 93.3 / 182.5 / 102.5 |
| Наблюдено за жизнь, среднее | 948.7 / 1150.7 / 1042.2 | 844.6 / 1406.3 / 768.4 |
| Столкновения, все запуски | 43 / 16 / 22 | 117 / 27 / 8 |
| Отключения, все запуски | 58 / 52 / 55 | 72 / 74 / 78 |

На test штрафуемый вариант теряет запись реже, чем дообученный контроль без штрафа (28 против 50), однако чаще исходного мозга (24). Он чаще восстанавливает запись и меньше сталкивается, но резко усиливает застой и уступает контролю по покрытию. Это **отрицательный результат полного критерия**, не выученный возврат и не признак «понял ценность капсулы». Со штрафом зафиксирован один LAB-кандидат пласта в 56 test-запусках (у исходного и контроля — 0/56): три разнесённые богатые пробы, не подтверждённый добываемый запас и не критерий выбора весов. Награда задана разработчиком; способность сети использовать её без деградации ещё требует работы.

Механика утраты/однократного штрафа подтверждена граничными тестами независимо от поведения. Новый LAB доступен отдельно; старые веса и режимы сохранены. Карта «глазами ровера» показывает капсулу по сохранённой оценке и убирает её после утраты записи, dev-карта продолжает показывать физическую истину. UI показывает известность, возраст, сигнал маяка, число потерь/повторных измерений и компонент последней оценки. Полные окна — локально `experiments/runs/capsule-full.json` с checksum в публичном отчёте.

Исторический `lidar-benchmark.json` закреплён за проверенной ревизией `e0336d56e7ed3947f3937a9f4cf2da031117ee3a`. Его старые хеши сверены с Git до правок; новый `capsule-benchmark.json` хранит хеши фактически исполнявшихся исходников, модели и протокол. Проверка опыта: `npm run train:capsule`; тесты: `npm test`; UI: `npm run dev` → «Разведка · память капсулы».

Следующее ограничение — полезное сохранение знания при продолжающейся разведке. Остаются работа с редким опытом столкновений и физическая польза возвращения/зарядки. Установка нового штрафа не закрывает эти задачи; автоматический возврат, защищённый слот, постоянный GPS или бонус за вращение не добавлены.

# Эксперименты

Первый реализованный опыт: [`../docs/WATER_EXPERIMENT.md`](../docs/WATER_EXPERIMENT.md). `npm run train:water` обучает локальную сеть; `npm run benchmark:water` повторяет оценку сохранённого мозга без обучения. В `water-benchmark.json` — протокол и агрегированные результаты, в `../models/water-dqn-v1.json` — веса. LAB-reset не является возрождением игрового ровера.

В Git хранить конфиги, манифесты и агрегированные метрики; большие журналы и модели — в локальном архиве/артефактах с ссылкой и checksum. Каждый опыт имеет seed, версию движка, модель, режим физики, лимиты памяти, энергию и наблюдения. Не делать выводов по одному удачному запуску.

Для живого обучения: [`../docs/ONLINE_LEARNING_AUDIT.md`](../docs/ONLINE_LEARNING_AUDIT.md). Последовательно `npm run audit:online` (выбор по validation), `npm run audit:online:known` (известные случаи), `npm run audit:online:test` (отложенный контроль выбранного варианта). Результаты сохраняются в `online-audit-validation.json`, `online-audit-diagnosis.json`, `online-audit.json`; подробные журналы окон — локально в игнорируемой `runs/`, с checksum в публичном отчёте. Это LAB-диагностика на внешнем компьютере, не бесплатная проверка качества внутри ровера.

Короткая память движения: `npm run train:motion`. Команда выполняет четыре тренировки (две с контекстом, две с замаскированными входами), выбирает внутри групп по живой validation, затем открывает новый test. Протокол — [`../docs/MOTION_CONTEXT_EXPERIMENT.md`](../docs/MOTION_CONTEXT_EXPERIMENT.md), агрегаты — `motion-benchmark.json`, выбранные модели — `../models/motion-context-dqn-v1.json` и `../models/motion-masked-dqn-v1.json`. Подробные окна — в `runs/motion-context-full.json`; checksum относится к содержимому JSON без последнего LF. Это долгий локальный опыт, не часть `npm test`.

Последовательность решений: `npm run train:sequential`. Старый bootstrap после действия сравнивается с замыканием на фактическом следующем наблюдении: по два тренировочных seed, новые карты 15001–17004, выбор до test. Протокол — [`../docs/DECISION_TRANSITIONS.md`](../docs/DECISION_TRANSITIONS.md), отчёт — `sequential-benchmark.json`, модели — `../models/motion-after-dqn-v2.json` и `../models/motion-decision-dqn-v2.json`. Подробные окна и фиксация выбора — локально в `runs/`. Старые motion/online-отчёты привязаны к Git-ревизии `dee8a83cfca0e9f3683873c1dd1fc1dace5577dc`; их source SHA-256 сверены с этой ревизией до изменения контроллера. Они описывают исторический алгоритм, а не новый код.

`npm run diagnose:sequential` воспроизводит шесть повторных запусков известных карт 42/4295, уже после фиксации выбранных весов. Отчёт `sequential-known.json` — диагностический случай, не ещё один набор выбора модели и не доказательство общего успеха.

Геометрия лидара 0.3.1: `npm run diagnose:lidar` воспроизводит пропуск близкого камня на известных картах с явно старым прибором; `npm run benchmark:lidar` сравнивает приборы с одинаковыми комплектными весами и включённым обучением, без отбора модели. Протокол — [`../docs/LIDAR_CORRECTION.md`](../docs/LIDAR_CORRECTION.md), отчёты — `lidar-diagnosis.json` / `lidar-benchmark.json`, подробные окна — локально в `runs/lidar-full.json` (checksum без последнего LF). 28 сценариев, 1 612 800 шагов. Исторический `sequential-benchmark.json` закреплён за сверенной ревизией `8b4a1ca3fd3f87f29d5e081231a339096624d00f`; для полного повторения прежних тренировок используйте их исходную ревизию, поскольку обычный прибор теперь исправлен. Регрессии 4233/4295 и `diagnose:sequential` явно выбирают `sampled-v1`.

# Протокол сотрудничества: автор + ChatGPT + Codex

## Роли

- **Владелец проекта:** задаёт направление, принимает спорные продуктовые решения, смотрит реальные результаты, утверждает большие изменения.
- **ChatGPT:** обсуждает идеи, предлагает эксперименты, обновляет концептуальные документы/реестр/задачи, анализирует результаты, может редактировать GitHub при наличии доступа.
- **Codex:** разрабатывает код, тестирует, документирует, создаёт коммиты и PR. Не вправе выдавать placeholder за обученную модель.

## Один общий контекст

Главные документы: `README.md` → `AGENTS.md` → `docs/IDEA_REGISTRY.md` → `docs/DECISIONS.md` → `docs/ROADMAP.md` → `docs/SIMULATION_CONTRACT.md`.

1. Новую идею записать в реестр с ID и статусом, прежде чем терять её в чате.
2. Перед разработкой оформить небольшой issue/эксперимент с гипотезой и критерием готовности.
3. Внести минимальное изменение, тесты, скриншот/демонстрацию при необходимости.
4. Обновить реестр, решения и `CHANGELOG.md`.
5. Каждому агенту прочитать последние коммиты перед работой; не перезаписывать параллельные изменения.
6. Спорные решения сначала обсудить с владельцем. Архивные идеи не удалять.

## Долгосрочная совместимость

- Схемы `save`, `telemetry` и `model` версионировать отдельно.
- Хранить `seed`, версию движка, пресет физики, ID обученной модели, конфигурацию сенсоров в метаданных опыта.
- Повторные попытки не должны уничтожать данные предыдущих.
- Ветки/PR предпочтительнее незаметного перезаписывания `main` при значимых изменениях.

## Готовая стартовая инструкция новому агенту

> Прочитай `AGENTS.md` и документы в нём. Мы строим честную 2D симуляцию лунного ровера с ограниченными сенсорами, батареей и памятью. Сохрани текущий работающий минимум и все идеи из реестра. Выбери один самый маленький следующий проверяемый шаг, укажи тесты и реальный статус без выдуманного обучения. При изменении поведения не давай ИИ доступ к полной карте. Обнови документы и CHANGELOG.
